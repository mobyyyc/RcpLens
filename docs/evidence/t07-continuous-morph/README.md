# Continuous receipt morph and navigation-height controls

All images and motion samples use an isolated fictional receipt store. No personal receipt data is included.

The tapped rectangle is frozen before navigation changes. A single animatable progress value interpolates position, paper length, tilt and preview/detail visibility. Reader content remains fully measured throughout closing, and its last scroll position is held for the return path. Neighbours and leather use the same animation transaction; the live stack returns only after the animation is removed. Expansion starts after geometry is measured, replacing the fixed 24ms delay. Review input decoding is outside geometry updates and unchanged purchase rows use equatable content.

The baseline bottom control measures 44 points, including circular Split and capsule actions. Capsules use native regular glass padding around a shared 30-point minimum label area; circular secondary actions use an explicit 44-point native interactive glass surface. Larger accessibility text can grow normally. Toolbar accessibility labels measure 36 points inside the painted 44-point toolbar glass, so tests check the visible baseline size rather than equating the inner label frame to the bottom capsule.

Final verification: six UI cases passed with zero failures on iPhone 18 Pro / iOS 27.0. They cover import contrast and 44-point size in light/dark; large text with reduced motion, opaque controls and increased contrast; dark review controls, green switch and readable footer; nine repeated returns including a scrolled return and newest paper; one/two/three receipt sandwich layering; long-paper footer and bounded scroll-end gap. The final circular sizing assertion and large-text accessibility paths were rerun after circle calibration; both passed. Simulator Release and unsigned physical iPhone SDK Release builds passed.

Final fictional playback was sampled at 30Hz through two complete entry/return pairs. The middle paper's visible top moves 277→169→277 points; the oldest paper moves 134→169→134. Maximum sampled top-edge steps are 16/16 and 6/5 points respectively, with no end-of-transition teleport. Contact sheets show movement and length change happening together. These are Simulator visual checks, not a device frame-rate benchmark. The motion recording precedes the final 3-point circle-size adjustment; the action bar height and animation code are unchanged. The raw 11-second recording remains local at `/tmp/sliplet-morph-final-motion/paper-motion.mp4`.

Earlier exploratory runs exposed oversized native-large controls and a missing bottom inset in the new overlay reader; both are fixed in the final run. Existing Xcode debugger lookup and SwiftUI layout diagnostics remain in local logs, with no final test failures. Real iPhone smoothness remains a user verification step.
