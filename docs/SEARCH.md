# Purchase history and local search · T07

T07 adds purchase search to **All receipts** while retaining the Paper lift wallet, encrypted record format, source evidence and exact split engine. Enter a merchant, item or SKU, combine it with month/store filters, and open a receipt or an individual match. All receipts and Starred exclude archived records by default; **Include archived** includes them. **Archive** is always separately browsable/searchable. Month sections run newest first, with **Date missing** last; unknown dates never become import dates. Filters use corrected merchant/date values and preserve unknown currencies/amounts.

A match opens its owning receipt with a concise match context. **Match details** shows the full current purchase and match provenance in a scrollable native sheet. **View matched original** opens existing evidence and highlights linked OCR observations where available; missing linkage never invents a region. The existing receipt-level Original control remains available. At accessibility text sizes the context becomes a single Match/details, linked-original and dismiss control row; full match text remains accessible through the details sheet and original image.

## Search contract

`Domain/ReceiptSearch.swift` indexes decrypted records in memory, rebuilt whenever the workspace's receipt array changes. It indexes current/original merchants, current descriptions and SKUs, original parsed descriptions and SKUs, linked OCR rows and otherwise unlinked raw OCR. A query requires all words within a single purchase/evidence candidate plus merchant fields; terms from different purchases cannot create a combined item. Merchant spacing/punctuation variants also work when combined with item/SKU words.

Case, accents, composed Unicode and full-width characters are folded using Foundation. Latin text supports token prefixes; continuous Chinese/Japanese/Korean text supports same-script substrings. Examples in verification are fictional, including `Crème fraîche`, `有机苹果`, Japanese and Korean text. This does not promise recognition accuracy, transliteration, pinyin, translation, simplified/traditional conversion or semantic similarity. A finite inspectable map handles common receipt abbreviations such as mlk/milk, brd/bread, chkn/chicken, org/organic and yog/yogurt; prefixes cover ordinary shortened words. Evidence is never rewritten. Punctuation-only queries return no matches. Queries over 512 characters ask for a shorter search rather than silently ignoring trailing terms.

Current and original SKU matches have different labels. Original descriptions/OCR remain findable after correction; obsolete intermediate correction labels are not indexed. If an original extracted item no longer has a current item identity/source link, its result is marked **Original extraction · removed from current receipt** and carries no current item ID or current amount. Unlinked OCR is marked **Original text · not linked to a current purchase**, without claiming it is an extracted/removed purchase. Printed numbers may appear in original text, explicitly as evidence. Such matches do not create purchase ownership or permit split finalization.

## Storage and lifecycle

No plaintext merchant/item/search index, query history or thumbnails are persisted. There are no new database tables, migrations, network requests, dependencies or model calls. `ReceiptWorkspace.receipts.didSet` rebuilds the memory index for committed create/edit/delete/organization/split changes, including the existing fallback state after a list refresh fails. Opening rebuilds from authenticated decrypted records; restart never depends on a stale disk index.

Background/protected-data loss clears the index, query, filters, include-archive choice, match selection and receipts synchronously through the existing session revocation, with presentation recreated under the new session ID. The existing encrypted storage/key-failure/asset deletion/backup limitations remain as documented in [STORAGE.md](STORAGE.md). This adds no new physical-device security claim.
